## Dataset inspection

The inspected snapshot is `643ece1b2e93f15022c83832302848c9978d5f05`: 194 episodes, 245,898 frames, 582 videos. Episodes 0–45 duplicate the September 4 capture; episodes 46–193 are the September 9 capture. All numeric rows were checked for nonfinite values. Frame/global indices, episode lengths, task indices and nominal timestamps were checked. Every video was decoded in full with FFmpeg, in addition to checking resolution, frame count and endpoints. Reports are in `outputs/hil194/`.

The task is **attach a green pipette tip**, without ejection. Automatic command-triggered ejection is disabled in the new profile. Manual E and scripted-demo ejection remain available.

| Channel | What the data actually provides |
|---|---|
| `observation.state` | 29 changing measured robot joints plus angular velocity and roll/pitch; the supported-base simulator does not reproduce the full base/IMU motion. |
| `action` | 35-dimensional high-level joint/mimic goal. The last six fields are constant navigation/root commands in this capture. |
| `action.low_level` | 29 recorded motor joint targets, used for dynamic replay. |
| `action.hand_right`, episodes 0–45 | Reconstructed constant `[0,0,0,0,639.3,777.3]`; original thumb commands are unrecoverable. |
| `action.hand_right`, episodes 46–193 | Recorded six-register commands. Most are constant within an episode but differ across episodes; eight episodes vary within the episode. |
| Hand feedback and hand force/tactile | Frozen in every episode; unsuitable as changing measured finger state or contact-force ground truth. |
| `observation.t_img_ms` | Strictly increasing real capture times; used for replay. |
| `observation.t_action_ms` | Frozen within every episode; actual command latency cannot be recovered. |

The real duration is typically about 5.5% longer than the nominal 60 fps timeline, with a maximum image gap of 236 ms. Replay preserves image-row pairing and the recorded image clock. It does not invent command timestamps. The source data is unchanged.

## Fixes made

- Removed the fixed hand-pose override from HIL194. The supplied hand command channels now drive the hand mapping. Frozen feedback is not substituted for measurements.
- Initialized unknown finger positions by closing them to first tool contact. Recorded servo targets stay unchanged, the pipette is not repositioned or welded, and poses are not overwritten during physics steps. This removes the approximately 11.5 mm startup finger/handle overlap. It does **not** eliminate subsequent grasp drift.
- Added separate camera references for the two captures. Episode-0 videos were verified byte-identical to the previous reference. The new session uses annotated episode-46 rack corners. These are approximate planar fits with assumed focal lengths and rack world pose, not calibrated intrinsics/extrinsics.
- Added a fixed bank of independently fitted episode references for difficult image registration. Each fallback uses one additional reference, with the existing feature-consensus and pose-fit checks; new fallback results are not recursively added to the bank.
- Updated HIL194 rack spacing from the nominal 9 mm assumption to a photo-derived 10.5 mm estimate. Rectified well rows/columns suggest about 10.5–11 mm under the existing 128 × 88 mm box-size assumption. A direct pitch measurement is still needed. The historical fitted episode-15 config keeps its original geometry.
- Added the red tape photographed above the black nozzle for episodes 46–193. See [the tape dimensions and mesh export](RED_TAPE.md).
- Corrected comparison playback to use the last available real frame at each simulation time. Sequential cached decoding replaces repeated seeks and avoids oversubscribing decoder threads.
- Added atomic mesh writes for concurrent evaluation, dataset/timing provenance in reports, and explicit dataset selection for historical fitted configs.

Camera names are deliberately preserved: `rgb` is fixed ego, `wrist_right` is the fixed side/bracket view, and **`wrist_left` is on the robot's right wrist**. Do not remap views based on their names alone.

## Validation and unresolved discrepancies

See `outputs/hil194/validation-summary.json`, `replay-metrics.csv`, and `replay-discrepancies.png` for the final full-episode results. `final-replays/input-config.json` freezes the exact tested configuration; each report records its hash. Each episode has a full report, applied workspace config and sampled trajectory. The validation compares simulated joints with measured joints; it also reports wrist FK error and pipette drift relative to the hand.

The frozen-config run completed **194/194 full episodes with finite states and no numerical warnings**. All **582/582 videos** decoded successfully. The test suite passed **45 tests and 18 subtests**. These checks establish data/replay integrity, not task success.

| Full-run metric | Result |
|---|---|
| Median right-arm joint RMSE | 0.01537 rad (0.881 degrees); worst episode 6.62 degrees |
| Median wrist-position RMSE against measured-joint FK | 9.43 mm; worst episode 117.20 mm |
| Median maximum pipette translation relative to hand | 23.61 mm; worst episode 93.78 mm |
| Median maximum pipette rotation relative to hand | 16.29 degrees; worst episode 65.60 degrees |
| Attachment events | Only episode 81, at 0.151 s, with 22.69 mm maximum attached lift |
| Maximum initial finger penetration after initialization | 0.020 mm |

The very early episode-81 attachment is not independently verified against the real video and must not be counted as a validated successful reproduction. The other 193 replays did not trigger attachment. Among seven paired comparisons, directly applying `action` produced arm RMSE of 1.88–3.82 degrees, versus 0.80–1.12 degrees with `low_level`.

**Some contacts are physically invalid despite finite simulation.** Episode 134 reached 5.34 mm pipette/rack penetration and a reported peak normal force of about 110,456 N. Several other episodes also produced forces in the tens of thousands of newtons. These are simulator artifacts, not credible pipetting forces; open-loop targets can continue driving into a misplaced or mismatched rack. Reliable object/robot registration, grasp calibration and contact/controller validation are still required. Reducing forces by silently changing recorded commands would no longer be the requested unchanged-action replay.

The camera/scene initializer accepts 160 episodes and rejects 34. Five accepted tip detections lie near cell boundaries. Accepted fits remain estimates. For rejected episodes, the batch evaluation explicitly used a session-reference layout **only to measure motion discrepancies**; it is not a recovered object placement or a successful demonstration. Normal `run.sh --scene-layout auto` rejects those cases and provides annotation instructions. To inspect their motion with the reference scene, explicitly use `--scene-layout fixed`.

Remaining limitations cannot be treated as solved by successful loading or finite physics:

1. **Grasp motion differs from the real recording.** The approximate hand model and register-to-joint mapping still permit translation and rotation of the pipette. Actual finger feedback is frozen, and wrist-to-tool placement/contact properties have not been measured. Removing initial overlap does not establish a calibrated grasp.
2. **Object interaction is not reproduced reliably.** Camera/world registration, tool mounting and precise tip/rack geometry remain approximate. Real recordings are labeled successful, but command replay does not thereby inherit that label. Check attachment events and contacts separately.
3. **No precise object-pose ground truth.** Nozzle error versus measured-joint FK assumes the configured wrist-to-tool transform; it is not an independently measured pipette trajectory. Four planar rack corners cannot validate every camera parameter, robot/world alignment or tool pose. The model also differs in background, hand shape, transparent surfaces and lighting.
4. **Contact and attachment mechanics remain estimates.** Tip retention/attachment uses weld constraints, and the mass, friction and contact response have not been identified from usable force measurements. Inspect `contact_diagnostics`, including penetration, before interpreting an attachment as physically credible.
5. **The deployed high-level controller is not reproduced.** The local TWIST2 real-server implementation converts a 35-dimensional mimic goal through a learned controller to 29 motor targets. The dataset does not pin the exact controller checkpoint, smoothing, rates or deployment configuration. Direct `--source action` servo playback bypasses that stage. `low_level` playback correctly avoids guessing it, but does not validate the VLA-to-motor pipeline.
6. **The robot base is supported.** Recorded IMU/base motion and balance-controller coupling are not reproduced by a fixed-pelvis model. The dataset's navigation commands are constant, but measured roll/pitch is not identically zero.

The next measurements that would reduce these ambiguities are the wrist-to-nozzle transform in the actual closed grasp, the correct hand model/register mapping, camera intrinsics/crops and camera-to-robot transforms, direct rack pitch and tip-bore measurements, and the real deployment controller/checkpoint. Hand/contact calibration also needs changing joint feedback or an independently observed tool pose and usable force measurements.

## Mixing simulation data with real VLA data

`outputs/hil194/training-contract.json` preserves the dataset modality mapping and known quality limits. The chosen VLA DataConfig determines the actual policy state/action dimensions; old piston checkpoint dimensions are not automatically applicable here.

- The dataset's default arm labels come from **`action`**, while motor replay uses **`action.low_level`**. Do not put motor targets into the high-level action column. Match the real controller interface, action units/order, normalization and chunk timing.
- Keep measured simulated joints as state and commanded targets as actions. They are different quantities.
- Preserve the physical camera assignments, aspect ratios, crops and preprocessing in real data, simulated data and deployment.
- Keep each real source episode and its simulated variants in the same train/validation partition. The older 46 episodes are already included in HIL194. `episode-provenance.json` corrects the new capture's source-metadata indices by the union offset of 46 for grouping.
- Retain the reconstructed-hand provenance; do not treat the old thumb constants or frozen feedback as measured grasp dynamics.
- Do not label unsuccessful or physically invalid replays as successful synthetic demonstrations. This work produces replay/audit artifacts, not a validated synthetic LeRobot fine-tuning dataset or a trained VLA.

## Reproduce the checks

```bash
~/miniconda3/envs/lerobot-act/bin/python tools/audit_hil_dataset.py \
  --dataset ~/.cache/huggingface/hub/datasets--jren313--g1-pipette-3view-hil194 \
  --output outputs/hil194/audit.json

~/miniconda3/envs/lerobot-act/bin/python -m g1_pipette_sim.episode_scene \
  --episodes all --cache outputs/hil194/scenes-final

OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
~/miniconda3/envs/lerobot-act/bin/python tools/evaluate_hil_replays.py \
  --episodes all --workers 8 --cache outputs/hil194/scenes-final \
  --allow-unresolved-layout --output outputs/hil194/final-replays

./run.sh --episode 46 --headless --compare --snapshot --duration 1 \
  --output outputs/hil194/final-camera-comparison
```

The scene-preparation command returns nonzero if any scene needs annotation, while retaining successful fits. The batch flag `--allow-unresolved-layout` is an explicit diagnostic fallback, not a confidence override for the image fitter. Use a new output directory when testing a different configuration so the frozen input and reports remain reviewable.
